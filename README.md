# Командная игра решений — LangGraph + LangChain

Локальный MVP по концепту из `V1concept - КЕЙСЫ примеры.docx` и схеме `V1conceptBlock.xlsx`: ведущий собирает 6–10 участников, приложение делит их на команды по 2–3 человека и проводит через истории, осложнения, разбор опыта и общий финал.

Два сценария: помощь домашнему животному и семейные решения о покупках. Основная версия запускается через `play.py`; `app.py` — совместимый вход к тому же интерфейсу. Описание раннего прототипа находится в [архивных заметках](docs/prototype-notes.md).

## Запуск

Нужен Python 3.12 или новее; зависимости зафиксированы и проверены в Python 3.12. Выполняйте команды из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
streamlit run play.py
```

Команда `streamlit run app.py` открывает ту же игру. В Windows активируйте окружение командой `.venv\Scripts\Activate.ps1`. Streamlit напечатает локальный адрес приложения.

По умолчанию доступен режим `mock`: ключ и сетевые запросы к модели не нужны. Введите разные имена участников, выберите настройки и создайте игру. Сохраните ID игры: он позволяет восстановить состояние из той же базы SQLite после перезапуска. Путь базы задается переменной `GAME_DB_PATH`; значение по умолчанию — `runtime/game.sqlite3`.

## Как проходит игра

1. Ввод имен и распределение в команды. Знакомство и обсуждение проводит ведущий.
2. `intro`: исходная ситуация, выбор варианта с объяснением или собственного плана — 180 секунд.
3. `decision`: следующий выбор, его последствия и риски — 120 секунд.
4. `depth`: случайное осложнение и свободный командный план — 90 секунд.
5. При неудаче или просрочке командного этапа — `education`: образовательный разбор и новый план. После успешного разбора команда возвращается в общий процесс.
6. Когда все команды готовы, открывается `final`: один общий план на 180 секунд. После финала выдаются символические дипломы.

На образовательный разбор отводится 180 секунд. Лимиты можно менять через сервис; в интерфейсе таймеры можно отключить. Время идет от входа на этап, проверка просрочки выполняется при отправке решения. Уточнение не выдает новый полный срок; время успешного API-запроса исключается из отсчета. Ошибка модели или валидации не сохраняет отправленный ответ.

Одинаковый `seed` и одинаковые входные данные воспроизводят распределение участников и выбор осложнений. Ветви, достроенные для MVP, помечены в каталоге как `mvp_extension`.

## Оценка

Политика по умолчанию — **`flexible`**: допустимы обоснованные альтернативы авторскому пути. Отдых сам по себе не является поражением; оценивается план и его связь с целью. Политика `author` включает заданные авторские поражения и авторскую игровую рубрику. Утверждения исходного концепта не являются медицинской или психологической диагностикой.

На первых двух этапах обычный вариант запускает заданное сюжетное последствие. Объяснение сохраняется, но модель на этом пути его не анализирует. Собственная альтернатива, свободное решение в глубине, образовательный разбор и общий финал передаются оценщику.

`MockEvaluator` — открытая детерминированная словарная эвристика, а не LLM. Он отмечает это в обратной связи, считает признаки действий, последствий, командной работы, заботы и рефлексии по шкале 0–2. Для продолжения нужны минимум 5/10 и хотя бы один признак действия; короткий или недостаточный ответ вызывает уточнение. Явные фразы бездействия, отказа помогать или покупки всего ведут к неудаче. Совпадения слов могут давать ошибочные оценки: этот режим нужен для воспроизводимого тестового прохождения.

### Подключение ChatGPT API

```bash
export OPENAI_API_KEY='ваш-ключ'
export OPENAI_MODEL='gpt-4.1-mini'
streamlit run play.py
```

В интерфейсе выключите «Демо без API» при создании новой игры; ключ также можно ввести в защищенном поле боковой панели. Существующая игра сохраняет свой режим оценки. Переменные окружения нужно задать до запуска; файл `.env` автоматически не загружается. Без ключа интерфейс сообщает о необходимости ключа и использует демо. Прямой вызов `create_evaluator(mode="openai")` без ключа сразу дает понятную ошибку. Не добавляйте настоящий ключ в Git.

`OpenAIEvaluator` использует LangChain `ChatPromptTemplate`, LCEL и `ChatOpenAI.with_structured_output(Assessment)`. В режиме API ответы, история и контекст команд отправляются OpenAI; запросы оплачиваются по тарифам API. Живой вызов OpenAI в этой поставке не проверен. Офлайн-проверки используют подставную модель.

## CSV-имитация и проверки

Временные ответы участников хранятся в `data/simulated_answers.csv`. Полное прохождение без API:

```bash
python -m game_agent.simulation --input data/simulated_answers.csv --output work/demo --db work/demo.sqlite3
```

Дополнительные случаи уточнения, неудачи и восстановления после тайм-аута находятся в `data/simulation_edge_cases.csv`; для их воспроизведения укажите этот файл в `--input` и новую папку `--output`.

Схема входных данных и экспортов описана в [сопоставлении концепта](docs/concept-mapping.md). Результаты демонстрации создаются в `work/demo`; SQLite хранит состояние отдельно. Это сценарные примеры для проверки приложения, а не ответы реальных игроков и не результаты живой модели.

Готовые протоколы четырех синтетических прохождений включены в [data/demo_results](data/demo_results). Полные исходные вложения, их SHA-256 и дословный извлеченный текст сохранены в локальном архиве. В публичный Git включены код и адаптированный игровой каталог.

```bash
python -m pytest -q
```

Проверки покрывают игровой граф, сохранение и конфликты версий, оценщики, CSV-прохождение и интерфейс. Количество и состав тестов смотрите в текущем каталоге `tests/`.

## Устройство и границы MVP

[Архитектура](docs/architecture.md) описывает настоящий граф, хранение состояния и место подключения API. [Сопоставление концепта](docs/concept-mapping.md) показывает реализованные требования, допущения и исключения.

- Приложение рассчитано на одного ведущего и общий локальный интерфейс. ID игры позволяет загрузить состояние; идентификации участников и ролевого доступа нет.
- SQLite и проверка версии защищают от перезаписи устаревшего состояния. Они не подтверждают личность отправителя.
- Для смешанных команд два разных авторских финала объединены в общий план о помощи и осознанном использовании ресурсов. Это допущение MVP.
- Распознавание речи, аудиоответы, выдача реальных призов и полноценная многопользовательская платформа не включены.
- После неудачи общего финала игра завершается разбором результата; восстановительный образовательный этап предусмотрен для командных историй.
