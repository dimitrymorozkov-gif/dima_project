# Концепт, игровые правила и CSV

Основа — два авторских кейса из `V1concept - КЕЙСЫ примеры.docx` и последовательность блоков из `V1conceptBlock.xlsx`. В локальном архиве сохранен `data/author_text.json`: 98 непустых абзацев DOCX и 29 подписей XLSX. Полные исходники и дословная выгрузка исключены из публичного Git. Рабочий каталог `data/game_catalog.json` адаптирует материал для исполняемой игры; не все последствия и вопросы являются дословными цитатами.

## Что реализовано и что принято как допущение

| Часть концепта | Статус | Поведение MVP |
| --- | --- | --- |
| Сбор 6–10 участников | Реализовано | Ввод уникальных имен с проверкой количества |
| Знакомство | Частично | Имена видны ведущему; разговор проводит сам ведущий |
| Деление на группы по 2–3 | Реализовано | Распределение с `seed`, все участники включены ровно в одну команду |
| Вводная история и данные | Реализовано | Этап `intro`, цель и варианты авторского кейса |
| Последующее решение | Реализовано | `decision`, выбранный вариант и его сюжетное последствие |
| Усложнение и ограничение времени | Реализовано | `depth`, одно воспроизводимое случайное событие и свободный ответ |
| Анализ полного решения | Реализовано с ограничением | Структурированный оценщик для альтернатив, глубины, разбора и финала; обычный вариант первых двух этапов запускает готовое последствие |
| Разные истории команд | Реализовано | Авторские `pet` и `family` назначаются командам по очереди |
| Проигрыш сценария | Адаптация | Команда проходит `education` и может вернуться к общей игре |
| Общий финал | Реализовано с допущением | Барьер готовности всех команд, затем один совместный план |
| Благотворительность и распродажа в одном финале | Допущение | Для смешанных сценариев объединены два разных авторских финала: помощь другим и осознанное использование ресурсов |
| Ветви, для которых автор не написал продолжение | Допущение | Сценарные расширения `source='mvp_extension'` для ожидания ветеринара, консультации психолога и семейного разговора |
| Развлекательный и образовательный контент | Частично | Сюжет, обратная связь, разбор решения и итоговый вывод; отдельного игрового медиа-контента нет |
| Награждение и призы | Частично | Символические дипломы; реальная выдача призов не подключена |
| Ввод речи и ее анализ | Не включено | Только текстовые ответы |
| Отдельные роли ветеринара, родственника, участника ДТП для всех команд | Не включено | Два игровых кейса; роли внутри решения распределяют сами команды |
| Индивидуальные аккаунты и независимые игровые клиенты | Не включено | Один ведущий, совместный локальный интерфейс и восстановление по ID |

В DOCX «Этап 1» явно пропущен. В MVP подготовка участников восстановлена по XLSX: сбор имен и разделение на команды. В `intro` начинается сама история из авторского «Этапа 2». Технические имена этапов поэтому не равны исходной нумерации.

## Правила переходов

Обычный порядок: `intro → decision → depth → ready`. Когда все команды в `ready`, игра переходит в `final → finished`.

- `continue` продвигает команду; успешный `depth` или `education` означает готовность к финалу.
- `clarify` оставляет текущий этап и просит дополнить ответ. Новый полный срок не выдается; время успешного API-запроса исключается из отсчета.
- `fail` или превышение срока командного этапа направляет в `education`. Успешный разбор сохраняет историю неудачи и возвращает команду в общий процесс.
- Неудача `final` завершает общую игру с разбором опыта и символическим дипломом участия.

Лимиты в секундах: `intro=180`, `decision=120`, `depth=90`, `education=180`, `final=180`. Проверка проводится при отправке, а не фоновым завершением этапа. Часы всех команд идут одновременно; выбор другой команды в интерфейсе не приостанавливает отсчет. Таймер — игровое правило, а не диагностический показатель.

Политика `flexible` выбрана по умолчанию: собственный аргументированный путь допустим. `author` включает авторские флаги неудачи и передает оценщику авторскую игровую рубрику. Например, поиск врача в домовом чате и навязанная спортивная секция имеют `author_fail=true`. Низкая оценка не означает оценку личности; исходные психологические утверждения не представлены как объективный диагноз.

При обычном варианте на `intro`/`decision` достаточно выбрать его и дать обязательное объяснение; сохраняются и выбор, и текст, но анализатор читает объяснение только при `choice_id=alternative`. Для семейного пути без обязательной покупки на втором шаге предлагается собственный план, а событие продолжает выбранную ветвь.

## Входная CSV-имитация

`data/simulated_answers.csv` содержит успешное синтетическое прохождение; `data/simulation_edge_cases.csv` — уточнение, неудачу и восстановление после тайм-аута. Это синтетические данные для `python -m game_agent.simulation`. Это вход проигрывателя, отдельный от экспортируемого протокола. Кодировка UTF-8; BOM допустим. Разделитель — запятая, поля с запятыми, кавычками и переносами заключаются в кавычки по правилам CSV.

| Столбец | Обязателен | Значение |
| --- | --- | --- |
| `run_id` | Да | ID независимой демонстрации: 1–64 латинские буквы, цифры, `_`, `-`; первый символ — буква или цифра |
| `seed` | Да | Целое число для распределения и осложнений |
| `participant_count` | Да | Число от 6 до 10; имена `Игрок 1` и далее создаются автоматически |
| `scenario_ids` | Да | `pet`, `family` или последовательность через `\|`, например `pet\|family`; назначение командам по кругу |
| `team_id` | Да | `team_1`, `team_2` и т. д.; на общем финале — `all` |
| `phase` | Да | `intro`, `decision`, `depth`, `education`, `final`; должна совпадать с фактическим этапом |
| `choice_id` | Да, ячейка может быть пустой | Идентификатор варианта или `alternative` на первых этапах; пусто для свободных этапов |
| `answer` | Да | Синтетический ответ длиной 1–12000 символов |
| `elapsed_seconds` | Да | Конечное неотрицательное число: желаемое время от начала текущего этапа |
| `expected_outcome` | Нет | Ожидаемый `continue`, `clarify` или `fail`; пустая ячейка отключает проверку |

Для одного `run_id` значения `seed`, `participant_count` и `scenario_ids` совпадают во всех строках. Порядок строк внутри демонстрации задает порядок отправок. Каждая демонстрация должна дойти до `finished`, иначе проигрыватель сообщает ошибку.

Проигрыватель всегда использует `mock`, политику `flexible` и включенные лимиты. Он не вызывает OpenAI и не ждет реальное время. Одни виртуальные часы общие для всех команд и никогда не идут назад: если предыдущая строка уже продвинула часы дальше указанного времени, фактическая длительность может оказаться больше `elapsed_seconds`. Для ожидаемого тайм-аута задайте значение выше лимита и учитывайте общие часы.

Доступные варианты из каталога:

| Сценарий | `intro` | `decision` |
| --- | --- | --- |
| `pet` | `vet`, `self_help`, `wait`, `neighbors`, `alternative` | `drive`, `call`, `home_vet`, `chat`, `alternative` |
| `family` | `gift`, `ignore`, `shout`, `psychologist`, `alternative` | После `gift`: `expensive`, `cheap`, `educational`, `sport`, `alternative`; после пути без покупки: `alternative` |

Событие не выбирается столбцом CSV: его определяет граф по `seed` и предыдущим решениям. Для вопроса, соответствующего именно этому событию, используйте каталог и экспортируемый протокол.

## Результаты проигрывания

```bash
python -m game_agent.simulation --input data/simulated_answers.csv --output work/demo --db work/demo.sqlite3
```

В новой папке создаются:

- `summary.json` — ID демонстраций и игр, число отправок, результаты команд и финала, имена файлов;
- `transcript_<run_id>.csv` — протокол всех отправок, UTF-8 с BOM;
- `game_<run_id>.json` — полный снимок игры с историей, выбранными событиями и символическими наградами.

JSON помечен `synthetic=true`, сводка — `mode=mock`. Для повторного запуска укажите новую папку `--output`: существующие результаты не перезаписываются. База `--db` хранит игровые снимки и может содержать несколько независимых запусков.

Экспорт интерфейса использует тот же `transcript_csv()`. В протоколе сохраняются ID игры и версии, команда, сценарий, этап, вопрос, событие, вариант, ответ, время, результат, обратная связь, уточнение, режим, происхождение оценки и суммарный балл. Полная разбивка по пяти осям, причины и образовательный вывод находятся в JSON-истории. Для сюжетных последствий и таймера балл пустой: модель их не оценивала.

Значения `provenance` отличают `authored_branch`, `mock_heuristic`, `openai`, `deepseek` и `timer`. Текстовые ячейки, начинающиеся с символов формул таблиц, экранируются при экспорте. Старый `data/example_answers.csv` относится к раннему прототипу и не является входом нового проигрывателя.
